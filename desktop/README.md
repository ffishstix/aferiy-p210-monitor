# Battery Watch for Windows

This is the tray application for [battery.fishstix.uk](https://battery.fishstix.uk). Left-click its icon to open a rounded bottom-right dock showing P210 charge, input and output power, runtime estimate, and update time. Click away to hide the dock. Battery controls opens all 16 editable settings available on the website, including outputs, charging, sound, and standby. Changes use the same protected cloud API and require a confirmed device response. The icon changes colour for charging, passing power through, discharging, low charge, stale readings, and faults. Windows notifications appear when the P210 starts discharging and below 15%, with follow-ups at 10% and 5%. It does not shut down the PC.

The app reads the public read-only status endpoint every 30 seconds. At startup and when you click Refresh in the dock, it asks the cloud collector for a new device reading and waits for that reading to be saved before displaying it. Battery controls require the control password, stored with Windows DPAPI for the current user. It has a “Start with Windows” switch and an Uninstall button in the dock. Uninstall removes that startup entry, the saved desktop password, and the running portable executable after it closes. It does not remove the shared .NET runtime, cloud history, or other battery tools. The dashboard URL is `https://battery.fishstix.uk`.

Direct downloads for x64, ARM64, and x86 Windows are on [the download page](https://battery.fishstix.uk/download.html). They are framework-dependent single-file executables and require the matching [Microsoft .NET 10 Desktop Runtime](https://dotnet.microsoft.com/en-us/download/dotnet/10.0) if it is not already installed. They are currently unsigned; SHA-256 checksums appear beside the downloads.

Version 1.2.1 and later checks the signed release manifest at `/updates/latest.json` on startup and every six hours. If a newer version exists, it verifies the publisher's RSA signature and the matching executable's SHA-256 hash, then restarts into the update. The tray menu also has “Check for updates”. An update failure leaves the existing executable in place and writes a diagnostic to `%LOCALAPPDATA%\AferiyMonitor\updates\last-update.log` if replacement fails. Version 1.1.0 did not have an updater, so install this version once from the download page.

To publish a future release, bump `<Version>` in `BatteryWatch.csproj`, then run `./publish-update.ps1` from PowerShell with a .NET 10 SDK. It builds all three architectures, updates the download page checksums, and signs `cloud/public/updates/latest.json`. The private signing key is stored only at `%LOCALAPPDATA%\AferiyMonitor\release-private.pem`; keep a secure backup because the app will reject releases signed by any other key. Commit the new binaries, download page, and manifest together so the existing GitHub workflow deploys them atomically. Never commit the private key.

The `--self-test` argument checks state classification and dock construction without opening the tray app. `--verify-update-manifest <path>` verifies a release manifest with the embedded public key. The ARM64 binary's PE architecture has been checked but needs a real ARM Windows test.

The dock also shows farm solar, generator and main-battery readings. The tray prompts to turn on the AFERIY input plug when the generator delivers at least 400 W while the P210 is discharging and the main bank is not draining, or when solar and main-bank charging are both at least 1200 W. That solar threshold covers the P210's maximum 1100 W AC setting plus a 100 W reserve. It prompts to turn the input plug off when the P210 draws over 50 W from AC and the farm bank receives under 100 W of net charge. Both feeds must be under two minutes old; the same advice must persist for two checks, and prompts are limited to one every 30 minutes. These are manual reminders, not automatic switching. Confirm the thresholds against real conditions before relying on them.
